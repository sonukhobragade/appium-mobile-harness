> Appium page-object harness with generation, oracles and Allure reporting

## Project

- **Stack**: Python, pytest, Appium, Selenium, Allure
- **Pattern**: page object over base_page, assert UI then verify via storage oracle
- **Interface registry**: supplied by the consuming project — single source of truth for all
  externally callable paths / commands / RPCs
- **Defect tracker**: `docs/bugs` (source of truth) + GitHub Issues (team mirror)

  stale local base produces silent bad diffs)

## Rules (Mandatory)

### Never work on the default branch
Create a feature branch first. Changes land via PR.

### Local gate before committing
Run **`/local-gate`** (`bash tools/local_gate.sh`) BEFORE every commit and again
before opening a PR. It runs lint + type check + the no-external-dependency test
set + a full collection smoke.

A red gate is fixed by **correcting the code**, never by weakening a check.

### Independent review before committing

**WAIT for the review. It GATES the commit — it never trails it.** The order on
every code change is:

1. **Run** the review over the working-tree diff.
2. **WAIT** and read the FULL findings. Never commit while a review is running,
   and never treat a fail-open hook pass as "reviewed".
3. **Analyse each finding** — real fix vs by-design. A by-design call must be
   justified, not assumed.
4. **Act** — fix the real ones in the SAME diff.
5. **Re-run** the affected tests so the fixes are validated.
6. **THEN commit.**

Committing first and reviewing afterward (then opening a follow-up "hardening" PR)
is the exact anti-pattern this forbids.

Keep diffs focused — a 600-line diff costs far more review than a 50-line one.
Then ask the reviewer two questions explicitly: **"is anything left / missed?"**
and **"should these cases be extended?"** Act on the answers before committing.

Skip only for pure doc/comment edits with no code.

### Never weaken a test to make it pass
A failing test is a **discovery**. FORBIDDEN: widening assertions, removing checks,
changing expected values, wrapping assertions in try/except.

If a test fails → investigate → **system defect**: document it in
`docs/bugs` + mark expected-failure. **Test defect**: fix the setup, never
the assertion.

### DRY checkpoint
At the 3rd copy-paste, STOP. Extract the helper first, refactor the existing
instances, then continue. After 5+ related tests, pause and review for patterns.

### Verify before claiming done
Never report work complete without running the verification command and reading
its output. Evidence before assertions.

## How to work

```
Install:    pip install -r requirements.txt
Test:       pytest
Single:     pytest -k
Lint:       python -m ruff check . || true
Typecheck:  true
Gate:       bash tools/local_gate.sh
```

## Restricted actions

| Level | Actions |
|---|---|
| REQUIRES user approval | Push to the default branch, force-push, close/merge PRs, delete branches, schema changes, dependency updates, disable hooks, weaken a check |
| ALLOWED freely | Read files, search code, run tests, read logs, dry-run collection, lint |

## Recovery

| Violation | Fix |
|---|---|
| Edited on the default branch | `git stash` → `git checkout -b feat/xxx origin/main` → `git stash pop` |
| Committed to the default branch | `git reset --soft HEAD~1` → new branch → commit there |
| Pushed to the default branch without a PR | Flag to the user immediately; do not force-push without approval |
| Weakened a check | Revert the assertion; document the defect instead |
| Failing collection | Fix the import/syntax error before proceeding |
